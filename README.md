# peni.sh

A small FastAPI service behind [https://peni.sh](https://peni.sh). It does two things:

1. **Serves a random image** from a directory on disk, wrapped in a green-on-black HTML page.
2. **Generates Wi-Fi SSID/password pairs** with an OpenAI model. Each password follows a simple rule
   derived from its SSID, so anyone who knows the rule can work it out. The response includes a hint
   that states the rule.

The whole app is `main.py`. `deploy.sh` and `nginx.conf` put it on a single Linux host behind nginx
with a Let's Encrypt certificate.

## Endpoints

| Method | Path                | Returns                                                          |
| ------ | ------------------- | ---------------------------------------------------------------- |
| GET    | `/`                 | HTML page showing one randomly chosen image                      |
| GET    | `/api/wifi`         | JSON `{ssid, password, hint}`                                    |
| GET    | `/api/images`       | JSON list of `{filename, path, size_bytes}` for indexed images   |
| GET    | `/image/{filename}` | The image file itself                                            |
| GET    | `/health`           | JSON `{status, image_count, image_dir}`                          |
| GET    | `/api/docs`         | Swagger UI (generated by FastAPI)                                |
| GET    | `/api/redoc`        | ReDoc                                                            |

```console
$ curl -s https://peni.sh/api/wifi | jq
{
  "ssid": "NightOwlCafe",
  "password": "nocafe",
  "hint": "First letters of each word + last word, lowercase"
}
```

(Example only. The model returns a different pair on every call.)

### How `/api/wifi` works

`generate_ssid_password()` sends a fixed prompt to the Chat Completions API with `temperature=0.9`
and `max_tokens=200`. The prompt asks for JSON only. Any surrounding Markdown code fence is stripped
before the JSON is parsed into the `SSIDPasswordPair` model.

If anything goes wrong (network error, API error, malformed JSON), the endpoint still returns
`200`. The response is then a deterministic fallback:

```json
{"ssid": "NetworkDown4821", "password": "nd4821", "hint": "Fallback mode: 'nd' + the number from SSID"}
```

A `NetworkDown…` SSID therefore means the OpenAI call failed. Check the error log.

### Images

On startup, and again whenever the cache is more than 5 minutes old, the app scans `IMAGE_DIR`
recursively. It keeps files ending in `.jpg`, `.jpeg`, `.png`, `.gif` or `.webp`, up to 1000 of them.
New images show up within 5 minutes without a restart.

`/image/{filename}` resolves the requested path and refuses anything outside `IMAGE_DIR`. It also
refuses any extension not on that list.

## Configuration

All configuration comes from environment variables.

| Variable         | Default                   | Notes                                                    |
| ---------------- | ------------------------- | -------------------------------------------------------- |
| `OPENAI_API_KEY` | none                      | **Required.** The app raises at import time without it.  |
| `OPENAI_MODEL`   | `gpt-4`                   | Any chat-completions model name                          |
| `IMAGE_DIR`      | `/var/www/peni.sh/images` | A missing directory is logged and treated as empty       |

CORS allows only `https://peni.sh`. To call the API from a browser on another origin, edit
`allow_origins` in `main.py`.

## Running locally

Requires Python 3.9 or newer (the code uses `Path.is_relative_to`).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install fastapi uvicorn openai

mkdir -p images            # drop a few images in here
export OPENAI_API_KEY=sk-...
export IMAGE_DIR="$PWD/images"

python main.py             # uvicorn on 127.0.0.1:8000 with --reload
```

Then open <http://127.0.0.1:8000/> or <http://127.0.0.1:8000/api/docs>.

## Deploying

`deploy.sh` sets up a fresh host. Run it as root from a checkout of this repo, after DNS for the
domain points at the machine:

```bash
export OPENAI_API_KEY=sk-...    # optional here; it can go in the .env file later
sudo -E ./deploy.sh
```

The script does the following, in order:

1. Installs nginx, certbot, Python and venv with the system package manager.
2. Creates a system user `penish` with no login shell.
3. Creates `/opt/penish`, `/var/www/peni.sh/images` and `/var/log/penish`.
4. Builds a venv in `/opt/penish/venv` and installs dependencies (see *Known issues*).
5. Copies `main.py` to `/opt/penish/` and writes `/opt/penish/.env` with mode `600`.
6. Installs and enables `penish.service`. The service runs uvicorn with 4 workers on
   `127.0.0.1:8000`, sandboxed with `ProtectSystem=strict`, `ProtectHome` and `NoNewPrivileges`.
7. Generates `/etc/nginx/dhparam.pem` and adds the `api` (10 r/s) and `images` (30 r/s) rate-limit
   zones to `/etc/nginx/nginx.conf`.
8. Brings up a temporary HTTP-only site and gets a certificate with `certbot certonly --webroot`.
9. Installs `nginx.conf` as the real site config, with rate limiting turned on. The real config
   redirects HTTP to HTTPS, serves TLS 1.2/1.3, sets HSTS and a few security headers, and caches
   `/image/` responses for 1 hour.
10. Enables `certbot.timer` for renewal and starts everything.

To deploy under a different name, change `DOMAIN` (and the other variables) at the top of
`deploy.sh`. The certificate paths in `nginx.conf` are hard-coded to `peni.sh`, so update those too.

### On the server

| Path                                  | What                                       |
| ------------------------------------- | ------------------------------------------ |
| `/opt/penish/main.py`                 | The app                                    |
| `/opt/penish/.env`                    | Environment file (holds the API key)       |
| `/opt/penish/venv/`                   | Python virtualenv                          |
| `/var/www/peni.sh/images/`            | Images to serve                            |
| `/var/log/penish/{app,error}.log`     | App stdout and stderr                      |
| `/etc/systemd/system/penish.service`  | systemd unit                               |
| `/etc/nginx/sites-available/peni.sh`  | nginx site                                 |

### Common operations

```bash
# Set or rotate the API key
sudo nvim /opt/penish/.env
sudo systemctl restart penish

# Ship a new main.py
sudo install -o penish -g penish -m 644 main.py /opt/penish/main.py
sudo systemctl restart penish

# Add images (picked up within 5 minutes, no restart needed)
sudo install -o penish -g penish -m 644 *.jpg /var/www/peni.sh/images/

# Logs. The unit sends output to files, so journalctl only shows start/stop events.
sudo tail -f /var/log/penish/app.log /var/log/penish/error.log
sudo tail -f /var/log/nginx/peni.sh_error.log

# Check that it's up
curl -s https://peni.sh/health | jq
```

## Known issues

These are real problems in the current code, listed so they don't surprise anyone:

- **No `requirements.txt`.** Without one, `deploy.sh` installs a fallback package list that leaves
  out `openai`. The service then crashes on import. Until a requirements file is added, run
  `sudo -u penish /opt/penish/venv/bin/pip install openai` after deploying.
- **Arch is not really supported by `deploy.sh`.** It tries `paru` before `pacman`, but paru refuses
  to run as root. The pacman branch uses Debian package names (`python3-pip`, `python3-venv`), and
  Arch's nginx has no `sites-available` directory. Debian and Ubuntu are the only paths that work.
- **Images in subdirectories are listed but not served.** The cache scans recursively, but
  `/image/{filename}` takes one path segment and looks only at the top level of `IMAGE_DIR`. Keep
  the image directory flat.
- **The fallback password is too short for WPA2.** `nd` plus four digits is 6 characters, and WPA2
  needs 8 to 63. Some of the example patterns in the prompt are short too, so model output can
  also come back under 8 characters.
- **The 502 branch never runs.** The JSON-parse failure raises an `HTTPException`, but the outer
  `except Exception` catches it and returns the fallback pair instead.
- **The root page puts filenames into HTML without escaping.** That's harmless while you control
  what goes into `IMAGE_DIR`, and a problem if anyone else can add files.
- **`/health` exposes the server path of the image directory.**
